This is a guide that explains how the epimight pipeline works, how you prepare your
data and how you run the pipeline on said data.

- Any data shown in this guide comes from [[../data/pipeline-tte.csv][this randomly generated time-to-event dataset]]
- All code shown in this guide have been written to [[./guide.R][this R file]]

* How it works

The pipeline estimates genetic correlation (~rg~) between 2 binary traits in a population/target cohort:

| Abbreviation | Description |
|--------------+-------------|
| ~t1~         | Trait 1     |
| ~t2~         | Trait 2     |

In order to do that it must first estimate the heritability (~h2~) of the two traits:

| Abbreviation | Description             |
|--------------+-------------------------|
| ~h2_t1~      | Heritability of trait 1 |
| ~h2_t2~      | Heritability of trait 2 |

It estimates heritability by comparing the cumulative incidence (~cif~) of the trait in the population
cohort and a family history cohort. The pipeline constructs the family history cohort by only keeping
individuals in the population cohort that has at least 1 relative with the trait. This means that for
each heritability estimate, the pipeline needs to know:

1. Which trait status/age to use in the 2 ~cif~ analyses and the family history cohort filter
2. Which kind of relatives to use in the family history cohort filter
3. What relatedness the selected kind of relatives have

"Kind of relatives" in this context means parents, full siblings, cousins or any other "kind" of relative.

The final estimate that is needed, is the "cross trait" cumulative incidence (~cif_cross~), which
uses:

1. The individuals trait status/age from trait 1
2. Family history cohort from trait 2

Once the pipeline has estimated that final cumulative incidence, it has produced 7 estimates in total:

| Abbreviation | Description                               |
|--------------+-------------------------------------------|
| ~cif_t1_pop~ | CIF of trait 1 in target cohort           |
| ~cif_t1_fh1~ | CIF of trait 1 in family history 1 cohort |
| ~cif_t2_pop~ | CIF of trait 2 in target cohort           |
| ~cif_t2_fh2~ | CIF of trait 2 in family history 2 cohort |
| ~h2_t1~      | Heritability of trait 1                   |
| ~h2_t2~      | Heritability of trait 2                   |
| ~cif_cross~  | CIF of trait 1 in family history 2 cohort |

The pipeline estimates the genetic correlation from 5 of these estimates and the relatedness of the
relatives in the family history 2 cohort:

To produce all of these estimates the pipeline needs a set of individuals, which for each trait contains:

- The individuals trait status (0 = censored, 1 = affected, 2 = competing risk)
- The individuals age at status (in years)
- The kind of relatives
- How many relatives the individual have of the specific relatives kind
- How many of those relatives have the trait

The pipeline accepts this data as a ~data.table~ with the following columns:

| Column name         | Description                                    |
|---------------------+------------------------------------------------|
| ~person_id~         | Unique identifier of the individual            |
| ~trait~             | Identifier of the trait                        |
| ~trait_status~      | 0 = censored, 1 = affected, 2 = competing risk |
| ~trait_age~         | Age of individual at the time of status        |
| ~relatives_kind~    | Identifier of the kind of relatives            |
| ~relatives_n~       | Amount of relatives                            |
| ~relatives_n_trait~ | Amount of relatives with trait                 |

and where the relatives are half siblings:

This ~data.table~ is called the time-to-event "pool". It's called a "pool" because all data is kept
there and only the relevant rows are pulled out when a genetic correlation is produced.

Besides the actual TTE data, the pipeline needs to know:

- Which trait, kinds of relatives and relatedness to use for heritability 1
- Which trait, kinds of relatives and relatedness to use for heritability 2

The next chapters shows you how this works in practice.

* Running the pipeline

To setup the pipeline, we start by importing the epimight library and loading the [[../../tests/data/pipeline-tte.csv][pipeline-tts.csv]]:

#+BEGIN_SRC R :exports code :eval no
library(dplyr)
library(readr)
library(data.table)
library(epimight)

tte <- read_csv(
  "./pipeline-tte.csv",
  show_col_type = FALSE,
  col_types = cols(person_id = col_character()),
) |> as.data.table()
#+END_SRC

And then create a new instance with our TTE pool:

#+BEGIN_SRC R :exports both
pipeline <- Pipeline$new(pool = tte)
#+END_SRC

#+RESULTS:

Now the pool is full of data and you can start running the pipeline to produce genetic correlations between specific traits.

Let's say we want to produce a genetic correlation between first diagnosis of "Schizophrenia" and
"Coronary Artery Disease" using parents as relatives. And we want to stratify the results on the
newly added column ~birth_year~ that contains the individuals birth year. We would then run:

#+BEGIN_SRC R :exports code :results output
results <- pipeline$run(
  heritability1 = list(
    index_trait    = "SCZ",
    relatives_kind = "parents",
    relatedness    = 0.5
  ),
  heritability2 = list(
    index_trait    = "CAD",
    relatives_kind = "half_siblings",
    relatedness    = 0.25
  ),
  stratify_columns = list("birth_year")
)
#+END_SRC

#+RESULTS:

This will output a named list that has the following members:

| Name     | Description                                                 |
|----------+-------------------------------------------------------------|
| rg       | All genetic correlations as a ~data.table~                  |
| h2       | All heritabilities as a ~data.table~                        |
| cif      | All cumulative incidences as a ~data.table~                 |
| metadata | Contains the version of pipeline and the arguments supplied |
