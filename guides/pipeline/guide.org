This is a guide that explains how the epimight pipeline works, how you prepare your
data and how you run the pipeline on said data.

- Any data shown in this guide comes from [[../data/pipeline-tte.csv][this randomly generated time-to-event dataset]]
- All code shown in this guide have been written to [[./guide.R][this R file]]

The pipeline has two interfaces that can be used to estimate genetic correlation between 2 binary traits
in a population/target cohort:

- Simple
- Advanced

Both interfaces uses the same time-to-event data format, but offers different levels of control.
The advanced interface gives the user full control of the underlying analyses (cif, h2, rg).
While the simple interface gives the user less control, but uses sane defaults that should work
for the majority of use cases.

This guide is separated into 4 chapters:

- Time-to-event input format
- Simple interface
- Output format
- Advanced interface

* Time-to-event input format

For each individual in the target cohort, the pipeline needs the following information for each trait
and kind of relatives:

- The individual's trait status (0 = censored, 1 = affected, 2 = competing risk)
- The individual's age at status (in years)
- How many relatives the individual have
- How many of them have the trait
- What "kind" of relative they are (parents, half siblings, cousins, etc.)

The pipeline accepts this data as a ~data.table~ with the following columns:

| Column name         | Description                                      |
|---------------------+--------------------------------------------------|
| ~person_id~         | Unique identifier of the individual              |
| ~trait~             | Identifier of the trait                          |
| ~trait_status~      | 0 = censored, 1 = have trait, 2 = competing risk |
| ~trait_age~         | Age of individual at the time of status          |
| ~relatives_kind~    | Identifier of the kind of relatives              |
| ~relatives_n~       | Amount of relatives                              |
| ~relatives_n_trait~ | Amount of relatives with trait                   |

Here's an example of what that data would look like for a single trait (first diagnosis of Schizophrenia)
and where the relatives are half siblings:

* Simple interface

To use the simple interface, we start by importing the epimight library and loading the test dataset [[../../tests/data/pipeline-tte.csv][pipeline-tts.csv]]:

#+BEGIN_SRC R :exports code :eval no
library(dplyr)
library(readr)
library(data.table)
library(epimight)

tte <- read_csv(
  "./pipeline-tte.csv",
  show_col_type = FALSE,
  col_types = cols(person_id = col_character()),
) |> as.data.table()
#+END_SRC

Then we create an instance of the pipeline with the test dataset:

#+BEGIN_SRC R :exports both
pipeline <- Pipeline$new(pool = tte)
#+END_SRC

#+RESULTS:

Once we have an instance of the pipeline, we need to tell the pipeline:

- Which trait should be "trait 1"
- Which trait should be "trait 2"
- What kind of relatives and relatedness to use for the two heritabilities

We supply this information as named arguments to the ~run~ function:

#+BEGIN_SRC R :exports code :results output
out <- pipeline$run(
  heritability1 = list(
    trait          = "SCZ",
    relatives_kind = "parents",
    relatedness    = 0.5
  ),
  heritability2 = list(
    trait          = "CAD",
    relatives_kind = "half_siblings",
    relatedness    = 0.25
  )
)
#+END_SRC

#+RESULTS:

The ~trait~ and ~relatives_kind~ values for the two heritabilities are just used as
filters on the time-to-event columns ~trait~ and ~relatives_kind~. In the test dataset our traits
are first diagnosis, where we use a 3 letter abbreviation of the diagnosed disorder. You can define your
traits and name them any way you like.

The simple interface acts as a thin layer of abstraction, which takes the given 6 arguments and
expands them into 14 advanced interface arguments that it uses to run the advanced interface.
It does this by making the following decision in the genetic correlation calculation:

- Use ~heritability1~ trait as index trait
- Use ~heritability2~ relatives trait and relatedness

* Advanced interface

The pipeline estimates genetic correlation (~rg~) between 2 binary traits in a population/target cohort:

| Abbreviation | Description |
|--------------+-------------|
| ~t1~         | Trait 1     |
| ~t2~         | Trait 2     |


In order to do that it must first estimate the heritability (~h2~) of the two traits:

| Abbreviation | Description             |
|--------------+-------------------------|
| ~h2_t1~      | Heritability of trait 1 |
| ~h2_t2~      | Heritability of trait 2 |

It estimates heritability by comparing the cumulative incidence (~cif~) of the trait in the population
cohort and a family history cohort. The pipeline constructs the family history cohort by only keeping
individuals in the population cohort that has at least 1 relative with the trait. This means that for
each heritability estimate, the pipeline needs to know:

1. Which trait status/age to use in the 2 ~cif~ analyses and the family history cohort filter
2. Which kind of relatives to use in the family history cohort filter
3. What relatedness the selected kind of relatives have

"Kind of relatives" in this context means parents, full siblings, cousins or any other "kind" of relative.

The final estimate that is needed, is the "cross trait" cumulative incidence (~cif_cross~), which
uses:

1. The individuals trait status/age from trait 1
2. Family history cohort from trait 2

Once the pipeline has estimated that final cumulative incidence, it has produced 7 estimates in total:

| Abbreviation | Description                               |
|--------------+-------------------------------------------|
| ~cif_t1_pop~ | CIF of trait 1 in target cohort           |
| ~cif_t1_fh1~ | CIF of trait 1 in family history 1 cohort |
| ~cif_t2_pop~ | CIF of trait 2 in target cohort           |
| ~cif_t2_fh2~ | CIF of trait 2 in family history 2 cohort |
| ~h2_t1~      | Heritability of trait 1                   |
| ~h2_t2~      | Heritability of trait 2                   |
| ~cif_cross~  | CIF of trait 1 in family history 2 cohort |

The pipeline estimates the genetic correlation from 5 of these estimates and the relatedness of the
relatives in the family history 2 cohort:



* Running the pipeline

To setup the pipeline, we start by importing the epimight library and loading the test dataset [[../../tests/data/pipeline-tte.csv][pipeline-tts.csv]]:

#+BEGIN_SRC R :exports code :eval no
library(dplyr)
library(readr)
library(data.table)
library(epimight)

tte <- read_csv(
  "./pipeline-tte.csv",
  show_col_type = FALSE,
  col_types = cols(person_id = col_character()),
) |> as.data.table()
#+END_SRC

And then create a new instance with our TTE pool:

#+BEGIN_SRC R :exports both
pipeline <- Pipeline$new(pool = tte)
#+END_SRC

#+RESULTS:

Now the pool is full of data and you can start running the pipeline to produce genetic correlations between specific traits.

Let's say we want to produce a genetic correlation between first diagnosis of "Schizophrenia" and
"Coronary Artery Disease" using parents as relatives. And we want to stratify the results on the
newly added column ~birth_year~ that contains the individuals birth year. We would then run:

#+BEGIN_SRC R :exports code :results output
results <- pipeline$run(
  heritability1 = list(
    index_trait    = "SCZ",
    relatives_kind = "parents",
    relatedness    = 0.5
  ),
  heritability2 = list(
    index_trait    = "CAD",
    relatives_kind = "half_siblings",
    relatedness    = 0.25
  ),
  stratify_columns = list("birth_year")
)
#+END_SRC

#+RESULTS:
