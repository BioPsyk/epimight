This is a guide that explains how the epimight pipeline works conceptually and how to run it.

- Any data shown in this guide comes from [[../data/pipeline-tte.csv][this randomly generated time-to-event dataset]]
- All code shown in this guide have been written to [[./guide.R][this R file]]

The pipeline has two interfaces that can be used to estimate genetic correlation between 2 binary traits
in a population/target cohort:

- Simple
- Advanced

Both interfaces uses the same time-to-event data format, but offers different levels of control.
The advanced interface gives the user full control of the underlying analyses (cif, h2, rg).
While the simple interface gives the user less control, but uses defaults that are sane the
majority of use cases.

This guide is separated into 4 chapters that can be read in order:

1. [[./#time-to-event-input-format][Time-to-event input format]]
2. [[./#simple-interface][Simple interface]]
3. [[./#output-format][Output format]]
4. [[./#advanced-interface][Advanced interface]]

* Time-to-event input format

For each individual in the target cohort, the pipeline needs the following information for each trait
and kind of relatives:

- The individual's trait status (0 = censored, 1 = affected, 2 = competing risk)
- The individual's age at status (in years)
- How many relatives the individual have
- How many of them have the trait
- What "kind" of relative they are (parents, half siblings, cousins, etc.)

The pipeline accepts this data as a ~data.table~ with the following columns:

| Column name         | Description                                      |
|---------------------+--------------------------------------------------|
| ~person_id~         | Unique identifier of the individual              |
| ~trait~             | Identifier of the trait                          |
| ~trait_status~      | 0 = censored, 1 = have trait, 2 = competing risk |
| ~trait_age~         | Age of individual at the time of status          |
| ~relatives_kind~    | Identifier of the kind of relatives              |
| ~relatives_n~       | Amount of relatives                              |
| ~relatives_n_trait~ | Amount of relatives with trait                   |

To look at some examples of valid data, we can download [[../data/pipeline-tte.csv][the randomly generated time-to-event dataset]]
as "pipeline-tte.csv" and load it:

#+BEGIN_SRC R :exports code :eval no
library(dplyr, quietly = TRUE, warn.conflicts = FALSE)
library(readr, quietly = TRUE, warn.conflicts = FALSE)
library(data.table, quietly = TRUE, warn.conflicts = FALSE)
library(epimight, quietly = TRUE, warn.conflicts = FALSE)

tte <- read_csv(
  "./pipeline-tte.csv",
  show_col_type = FALSE,
  col_types = cols(person_id = col_character()),
) |> as.data.table()
#+END_SRC

some versions of dplyr removes precision of large numbers in join operations. This means that
multiple unique individuals gets interpreted as a single unique individual.

The test data defines traits as "first diagnosis of disorder" and it contains two traits:

- ~SCZ~ = First diagnosis of Schizophrenia
- ~CAD~ = First diagnosis of Coronary Artery Disease

And it contains two different kinds of relatives:

- ~half_siblings~
- ~parents~

* Simple interface

To use any interface of the pipeline, we first need to create an instance of the pipeline
and pass it our time-to-event data:

#+BEGIN_SRC R :exports both
pipeline <- Pipeline$new(pool = tte)
#+END_SRC

#+RESULTS:

It's called a "pool" because all data is kept there and only the relevant rows are pulled
out of the pool during analysis. It's designed this way for simplicity, but also so that
the time-to-event data is immutable during analysis.

The simple interface allows you to specify index traits, relatives kind and relatedness
of the two heritabilities, along with the columns to stratify the results on:

#+BEGIN_SRC R :exports code :results output
out <- pipeline$run_default_rg(
  heritability1 = list(
    trait          = "SCZ",
    relatives_kind = "parents",
    relatedness    = 0.5
  ),
  heritability2 = list(
    trait          = "CAD",
    relatives_kind = "half_siblings",
    relatedness    = 0.25
  ),
  stratify_columns = list("birth_year")
)
#+END_SRC

#+RESULTS:

It will automatically use:

- The trait from ~heritability1~ as the index trait for the cross trait ~cif~
- The relatives cohort from ~heritability2~ for the cross trait ~cif~
- The relatedness from ~heritability2~ for the ~rg~ calculation

** Output format

Both interfaces has the same output format, a single named list with the following members:

| Name         | Description                                       |
|--------------+---------------------------------------------------|
| metadata     | Metadata of the analysis performed                |
| results      | All genetic correlations as a single ~data.table~ |
| intermediate | All intermediate results as separate outputs      |

** Results cache

When the pipeline is run, under the hood it produces these intermediate analysis results,
that are used to produce the genetic correlation:

| Name         | Description                                       |
|--------------+---------------------------------------------------|
| ~cif_t1_pop~ | CIF for trait 1 in target cohort                  |
| ~cif_t1_fh1~ | CIF for trait 1 in target family history cohort 1 |
| ~cif_t2_pop~ | CIF for trait 2 in target cohort                  |
| ~cif_t2_fh2~ | CIF for trait 2 in family history cohort 2        |
| ~cif_cross~  | CIF for trait 1 in family history cohort 2        |
| ~h2_t1~      | Heritability of trait 1                           |
| ~h2_t2~      | Heritability of trait 2                           |

If we changed the relatives in ~heritability2~ to "parents" and rerun the
pipeline, the only intermediate results that would come out different
would be:

- ~cif_t2_fh2~
- ~cif_cross~
- ~h2_t2~

Since the pipeline is deterministic, all other intermediate results would
be identical, since their arguments wasn't changed.

In order not to waste time on producing results that have already been produced,
the pipeline caches all results (cif, h2, rg). If we would execute the
~run~ function twice, with the same arguments, the second time would return
immediately, since it wouldn't run any of the analyses and just return the
cached results.

The pipeline has a function called ~clear_results~ that can be used to clear the
results cache. It also has functions to add and get results from the cache, but
those functions are used internally by each analysis function.

* Advanced interface

The advanced interface consists of 3 functions:

- ~run_cif~
- ~run_h2~
- ~run_rg~

These functions form a hierarchy, where their results are used as inputs to the other more complex functions.

The starting function is the one producing cumulative incidences, called ~run_cif~:

#+BEGIN_SRC R :exports code :results output :tangle no
advanced_cif_pop <- pipeline$run_cif(
  index_trait = "SCZ"
)

advanced_cif_cross <- pipeline$run_cif(
  index_trait      = "SCZ",
  relatives_trait  = "CAD",
  relatives_kind   = "parents",
  stratify_columns = list("birth_year")
)
#+END_SRC

The next function is the one producing heritability, called ~run_h2~:

#+BEGIN_SRC R :exports code :results output :tangle no
advanced_h2_t1 <- pipeline$run_h2(
  cif_pop = list(
    index_trait      = "SCZ",
    stratify_columns = list("birth_year")
  ),
  cif_fh = list(
    index_trait      = "SCZ",
    relatives_trait  = "SCZ",
    relatives_kind   = "half_siblings",
    stratify_columns = list("birth_year")
  ),
  relatedness = 0.25
)
#+END_SRC

This function passes the arguments ~cif_pop~ and ~cif_fh~ as input arguments to the ~run_cif~ function.
It then uses the returned results along with the relatedness argument to perform the heritability calculation.

The final function is the one producing the genetic correlation, called ~run_rg~:

#+BEGIN_SRC R :exports code :results output :tangle no
advanced_rg <- pipeline$run_rg(
  h2_t1 = list(
    cif_pop = list(
      index_trait      = "SCZ",
      stratify_columns = list("birth_year")
    ),
    cif_fh = list(
      index_trait      = "SCZ",
      relatives_trait  = "SCZ",
      relatives_kind   = "half_siblings",
      stratify_columns = list("birth_year")
    ),
    relatedness = 0.25
  ),
  h2_t2 = list(
    cif_pop = list(
      index_trait      = "CAD",
      stratify_columns = list("birth_year")
    ),
    cif_fh = list(
      index_trait      = "CAD",
      relatives_trait  = "CAD",
      relatives_kind   = "half_siblings",
      stratify_columns = list("birth_year")
    ),
    relatedness = 0.25
  ),
  cif_cross = list(
    index_trait      = "SCZ",
    relatives_trait  = "CAD",
    relatives_kind   = "parents",
    stratify_columns = list("birth_year")
  ),
  relatedness = 0.5
)
#+END_SRC

This function passes:

- The arguments ~h2_t1~ and ~h2_t2~ as input arguments to the ~run_h2~ function
- The argument ~cif_cross~ as input arguments to the ~run_cif~ function

It then uses the returned results along with the relatedness argument to perform the genetic
correlation calculation.

By using the advanced interface, we have total control over each distinct analysis.

Each of these functions uses the same output format as the simple interface, a named list
with the following members:

| Name         | Description                                        |
|--------------+----------------------------------------------------|
| results      | Analysis results as a single ~data.table~          |
| intermediate | All intermediate results as separate ~data.tables~ |
| args         | Arguments supplied to the interface                |
